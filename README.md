# نجم نت — بوابة MikroTik Hotspot

صفحات تسجيل دخول وحالة الاتصال لشبكة نجم نت. المشروع مخصص لوضع الملفات التشغيلية في **مجلد HTML للـ Hotspot** المحدد في MikroTik RouterOS. لا ترفع مجلد `tests` أو `.github` إلى الراوتر؛ هما مخصصان للمصدر والاختبارات.

## التثبيت

1. احتفظ بنسخة من ملفات Hotspot الحالية ومن إعدادات البروفايل.
2. انسخ ملفات `*.html` ومجلدات `css` و`js` و`font` و`img` إلى مجلد HTML الخاص بالهوتسبوت.
3. تحقق من إعداد `html-directory` الخاص ببروفايل الهوتسبوت ووسائل تسجيل الدخول المفعلة.
4. افتح صفحة الدخول من هاتف غير مسجل، وتحقق من تسجيل الدخول ثم الحالة ثم تسجيل الخروج. اختبر كل خيار سرعة مع User Manager قبل الاعتماد.

## متطلبات وتشخيص

- تحتفظ الصفحة بطرق اختيار السرعات ومنافذها **62021 و62022 و62023 و62024** وإرسال `domain` كما كانت في المصدر السابق. يجب أن تكون خدمات السرعات المخصصة مضبوطة على الراوتر؛ هذه الصفحة لا تضيفها ولا تفتحها آليا.
- **HTTP-CHAP مدعوم الآن:** يتلقى المتصفح تحدي المصادقة من صفحة `/login?var=najmChap` (المتغيرات لا تتوافر في index.html)، ثم يحسب `MD5(chap-id + password + chap-challenge)` محليا ويرسل التجزئة فقط. إذا أعاد الراوتر تحديا تالفا، لا يتم إرسال كلمة المرور كبديل نصي.
- **HTTP-PAP/HTTPS:** عند عدم وجود تحدي CHAP، يحتفظ الدخول بالآلية القديمة المخصصة للكرت ذي الرقم فقط. يجب أن يتوافق `login-by` مع قاعدة البيانات الفعلية، ويفضل HTTPS لكلمات المرور التي ترسل بدون CHAP.
- **كلمة مرور الكرت:** الإعداد الافتراضي في `index.html` هو `cardPasswordMode:'empty'` (كلمة مرور فارغة للمصادقة بالرقم فقط). إذا كانت كلمات مرور الكروت مطابقة لأسمائها، استخدم `cardPasswordMode:'username'` بعد التأكد من إعدادات الراوتر؛ لا تفترض ذلك تلقائيا.
- **ملف إلزامي جديد:** `js/chap.md5.js` يجب رفعه إلى مجلد HTML مع بقية ملفات `js`. إذا تعذر فك التحدي المشفر من الراوتر، تنتقل البوابة إلى نموذج `/login?var=najmNative` الذي يحسب CHAP من متغيرات MikroTik الأصلية دون إرسال كلمة المرور نصيا؛ يعيد ملء رقم الكرت مؤقتا من sessionStorage (دقيقتان) دون وضعه في الرابط. ملفات الكاميرا لم تُعدّل.
- التعرف الضوئي على صورة الكرت يعتمد على **Tesseract.js** من CDN، وقد يتعذر قبل السماح بالوصول إليه في Walled Garden. الإدخال اليدوي يبقى متاحا دائما.
- عند فحص الأخطاء على الراوتر، راجع (بدون نشر بيانات اعتماد المستخدمين) الأوامر `/ip hotspot profile print detail`، و`/log print where topics~"hotspot"`، و`/log print where topics~"radius"` للتحقق من سبب الرفض الحقيقي.
- لا تفترض الصفحة أن أي رد RADIUS مبهم يثبت انتهاء الرصيد أو صلاحية الكرت. تعلن الأسباب المؤكدة بحسب الرسالة الأصلية فقط.
- خطا التسجيل والدخول الحقيقي لا يمكن تأكيدهما من المتصفح وحده عند انقطاع الاتصال. يجب مطابقة السجلات مع `/log print` وUser Manager عند الحاجة.
- لا تعيد كتابة متغيرات MikroTik من الشكل `$(...)` عند نقل الملفات؛ يستبدلها الراوتر بنفسه.

## التحقق البرمجي

```sh
node --check js/portal.core.js
node --check js/chap.md5.js
node --check js/cam.najm.js
node --test tests/*.test.cjs
```

**فصل التشغيل:** ملفات `*.html` و`css/` و`js/` و`font/` و`img/` فقط. ملفات الاختبار وGitHub Actions لا تحتاج إلى النقل للراوتر.
## إصلاح تحدي CHAP على RouterOS (21 نوفمبر 2026)

عولج خطأ «تعذر قراءة تحدي المصادقة من الراوتر» عند تحويل `$(chap-id-esc)` و`$(chap-challenge-esc)` إلى قيم URL مشفرة: يرسل MikroTik البايتات عادة بصيغة ثمانية `\371`، وتصل بعد الترميز مثل `%5C371`. يجب فك ترميز URL أولا ثم تحويل السلاسل الثمانية إلى بايتات قبل حساب MD5. يدعم الإصلاح أيضا تمثيل `%F9` والصيغة الثمانية المباشرة دون تخفيف رفض التحديات التالفة.

إذا كانت الصفحة مثبتة على الراوتر، أعد رفع `js/chap.md5.js` و`index.html` معا (مع باقي الملفات عند التنصيب لأول مرة)، ثم افتح `http://<hotspot-ip>/index.html?v=chapfix1` لتجنب التخزين المؤقت. لا تتطلب هذه المعالجة تغيير بيانات الكروت أو السرعات. **لم يُمس ملف الكاميرا**. عند استمرار الرفض بعد بدء إرسال الطلب، تحقق من كلمة مرور الكرت الفعلية وطرق `login-by` وسجل RADIUS؛ لا تغيّر `cardPasswordMode` تخمينيا.

## تدقيق إضافي لمسار تسجيل الدخول والحزمة النهائية (2026-11-21)

- في بعض إعدادات MikroTik يعيد طلب `POST /login?var=callBack` صفحة HTML بسبب التحويل إلى `alogin.html` رغم نجاح التسجيل. تتأكد الصفحة الآن من `/status?var=callBack` قبل إعلان الخطأ؛ تُقبل النتيجة فقط عند تطابق اسم المستخدم المتصل مع الكرت الذي حاول الدخول.
- في الحالات الملتبسة تُجرى محاولتا تحقق GET فقط، **دون إعادة إرسال طلب POST** أو تخمين صلاحية الكرت.
- تظل المصادقة الاحتياطية الأصلية `/login?var=najmNative` كما هي لتحديات CHAP غير المقروءة. لا تسمح بالتحويل إلى كلمة مرور نصية عند وجود تحدي CHAP.
- كل تشغيل ناجح من GitHub Actions يفحص JavaScript ويشغل اختبارات الانحدار ثم يبني ملف ZIP للتثبيت على الراوتر ويولد ملف `SHA256SUMS.txt` ويرفعهما كـ Artifact. **لا يُنشأ الإصدار إذا فشلت الاختبارات**.
- لا ترفع ملفات `.github` أو `tests` أو README إلى MikroTik؛ استخدم محتويات ZIP التشغيلية فقط. لم يُجرَ أي تعديل في كود أو واجهة الكاميرا أو قيم منافذ السرعات.
- اختبار المتصفح المحلي على جهاز المحاكاة غير متاح في هذه البيئة. لا تعتبر اختبارات CI بديلا عن اختبار عملي للكروت على RouterOS v6 وUser Manager.
